Network Traffic Analyzer for DDoS Detection

// PACKET ANALYSIS • ANOMALY DETECTION • REAL-TIME ALERTING

project_overview.md

Project Overview

This project focuses on building a network traffic analyzer capable of detecting Distributed Denial-of-Service (DDoS) patterns. The system captures and inspects network packets, extracts relevant features (packet rate, protocol distribution, source diversity), and flags anomalous traffic that matches common DDoS signatures such as SYN floods, UDP floods, and volumetric attacks.

The goal was to understand how real-time traffic analysis and simple rule-based / statistical detection can surface attack traffic before it becomes critical.

Why This Project

DDoS remains one of the most common network-layer threats. Building a detector from scratch helped me understand packet-level behaviour, threshold tuning, and the practical challenges of reducing false positives while still catching real attacks. This knowledge also feeds into larger monitoring systems such as NetWatch SOC.

Methodology

  1. Captured live or simulated network traffic using packet sniffing tools.
  2. Parsed packets and extracted key features (source IP, destination port, protocol, packet size, inter-arrival time).
  3. Defined detection rules / thresholds for common DDoS indicators (sudden spike in packet rate, high SYN ratio, many unique sources targeting one host, etc.).
  4. Implemented alerting logic to raise notifications when thresholds were crossed.
  5. Tested the detector against normal traffic and simulated attack traffic.
  6. Documented detection results, limitations, and possible improvements.

Key Findings & Results

  • Successfully identified volumetric and protocol-based flood patterns in test traffic.
  • Observed that simple rate-based thresholds work well for clear floods but need tuning for low-and-slow attacks.
  • Gained practical experience in packet parsing and real-time analysis pipelines.
  • Identified natural next steps: combining rule-based detection with statistical / ML models (as later done in NetWatch).

Tools & Techniques

  • Python + Scapy (or equivalent) for packet capture and parsing
  • Wireshark for offline analysis and validation
  • Custom scripts for feature extraction and threshold-based detection
  • Basic alerting / logging of suspicious flows

Challenges & Lessons Learned

  • Balancing sensitivity vs. false positives — aggressive thresholds generate noise on busy networks.
  • Importance of baseline traffic knowledge before setting detection rules.
  • Real-time processing requires careful performance considerations (buffering, sampling).
  • Clear logging and evidence retention are essential for later investigation of alerts.
